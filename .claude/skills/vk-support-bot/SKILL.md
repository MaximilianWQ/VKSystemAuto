# Бот поддержки ВКонтакте + веб-дашборд оператора

Бот живёт внутри сообщества ВК, принимает обращения пользователей в личные сообщения сообщества,
отвечает на частые вопросы сам и передаёт остальное оператору. Оператор работает **в веб-дашборде**,
не в ВК. Этот файл — договорённости проекта и места, где VK API отличается от Telegram и где чаще
всего ошибаются.

## Решения по этому проекту

Приняты на этапе брейншторма, не пересматривать без явной просьбы:

- **Рабочее место оператора — веб-дашборд.** ВК-команды оператора (`/chat`, `/close`) не делаем:
  именно они были источником боли в старом боте. В ВК у оператора есть только `/link` для
  регистрации passkey.
- **Оператор один** (он же админ). Ролей, назначений и «занято другим оператором» нет.
- **Вход в дашборд — только passkey (WebAuthn).** Паролей нет. Первичная регистрация — через
  одноразовую подписанную ссылку, которую бот присылает в ВК владельцу `ADMIN_ID` по команде `/link`.
- **Дашборд — PWA** с поддержкой iOS и веб-пушами.
- **Один сервис на Railway**: FastAPI обслуживает вебхук ВК, REST, WebSocket и статику PWA.
  Плюс отдельный Postgres. Redis нет, очередь и pub/sub — внутрипроцессные.
- **Вложения:** входящие показываем все (фото, видео, документы, голосовые, стикеры, геопозиция);
  исходящие от оператора — фото и файлы. Голосовые и видео от оператора в первую версию не входят.

## Стек

- Python 3.12, `vkbottle` (async) — как **клиент VK API**, без её собственного `Bot`-рантайма:
  `vkbottle.API`, `PhotoMessageUploader`, `DocUploader`, `Keyboard`, `VKAPIError[code]`.
  Перед использованием любого метода библиотеки сверься с актуальной документацией через Context7 —
  API vkbottle менялся между версиями, по памяти не писать.
- Веб: FastAPI + uvicorn. Он же принимает Callback API, он же отдаёт дашборд.
- Long Poll — только для локальной разработки, переключается переменной `VK_MODE=longpoll|callback`.
- Postgres через `asyncpg`, пул соединений. Миграции — простые SQL-файлы в `migrations/`,
  применяются при старте.
- Passkey: `py_webauthn`. Пуши: `pywebpush` + VAPID.
- Фронт: React + TypeScript + Vite + Tailwind + Motion, собирается в статику.
- Деплой: Railway, Dockerfile, порт из `$PORT`.

## Переменные окружения

`VK_GROUP_TOKEN`, `VK_GROUP_ID`, `VK_CONFIRMATION_CODE`, `VK_SECRET_KEY`,
`VK_API_VERSION` (по умолчанию `5.199`), `ADMIN_ID`, `DATABASE_URL`, `VK_MODE`,
`WORK_HOURS` (например `10-19`), `TZ`,
`WEBAUTHN_RP_ID`, `WEBAUTHN_ORIGIN`, `SESSION_SECRET`,
`VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`.

Реальные значения — только в Railway Variables. В репозитории держим `.env.example` без значений,
`.env` в `.gitignore`. Токены не логировать и не выводить в ответах.

`WEBAUTHN_RP_ID` и `WEBAUTHN_ORIGIN` привязаны к домену: при переезде с `*.up.railway.app` на свой
домен их надо поменять **и заново зарегистрировать passkey** — старый ключ работать не будет.

## Чем VK отличается от Telegram

1. **Токен сообщества.** Нужны права `messages` и `manage`. В настройках сообщества должны быть
   включены «Сообщения сообщества» и «Возможности ботов».
2. **Callback API — подтверждение.** На событие `type=confirmation` сервер отвечает строкой из
   `VK_CONFIRMATION_CODE` (просто текст, не JSON). На все остальные события — строкой `ok` со
   статусом 200, быстро. Если `ok` не пришёл, ВК повторяет событие — поэтому обработку делаем
   в фоне, а дубли отсекаем по `event_id`.
3. **Проверка секрета.** Каждое входящее событие содержит `secret` — сверяем с `VK_SECRET_KEY`,
   иначе 403. Также сверяем `group_id`.
4. **`random_id` обязателен** в `messages.send`. Генерируем уникальный int32 на каждое сообщение:
   повтор с тем же `random_id` ВК считает дублем и не доставляет. Это удобно для ретраев — при
   повторной отправке того же сообщения используем тот же `random_id`. Поэтому `random_id`
   генерируется **один раз при постановке в `outbox`**, а не при каждой попытке.
5. **Писать можно только тем, кто разрешил.** Пользователь должен сам написать сообществу или
   разрешить сообщения. Ошибка `901` = сообщения запрещены: помечаем пользователя
   `can_write=false` и больше не шлём, без ретраев.
6. **Лимиты.** Для токена сообщества около 20 запросов в секунду. Ошибка `6` (too many requests) —
   пауза и повтор с экспоненциальной задержкой; ошибка `9` (flood control) — не повторять сразу.
   Отправку делаем через общую очередь с ограничителем скорости.
7. **`peer_id`.** Личка: `peer_id = user_id`. Беседа: `peer_id = 2000000000 + chat_id`.
   Отвечаем всегда в `peer_id`, из которого пришло сообщение.

## Отправка идёт только через outbox

Railway перезапускает процесс в любой момент. Прямой вызов `messages.send` из обработчика теряет
сообщение при рестарте. Любая исходящая отправка:

1. пишется строкой в таблицу `outbox` (с уже сгенерированным `random_id`);
2. фоновый воркер забирает строки, шлёт с ограничением скорости, обрабатывает `6/9/901`;
3. успех/провал пишется обратно в строку.

## Вложения

**Входящие.** Ссылки ВК на документы и голосовые подписанные и протухают. Не отдаём их в браузер
напрямую — отдаём через свой эндпоинт `/api/attachments/{id}`, который при 403 перезапрашивает
свежий URL через `messages.getById` и стримит. Прямых файлов видео VK API не отдаёт: показываем
превью и штатный плеер ВК.

**Исходящие.** Фото — `photos.getMessagesUploadServer` → POST → `photos.saveMessagesPhoto`.
Файлы — `docs.getMessagesUploadServer` → `docs.save`. Пользуйся аплоадерами vkbottle,
руками мультипарт не собирать.

## Клавиатуры

Клавиатура — JSON в параметре `keyboard`. Пользоваться билдером vkbottle, руками JSON не собирать.

- Обычная: до 5 кнопок в ряду, до 10 рядов, до 40 кнопок. Inline (`inline: true`): до 5 в ряду,
  до 6 рядов, до 10 кнопок.
- Цвета: `primary`, `secondary`, `positive`, `negative`.
- `payload` — JSON-строка до 255 символов. Маршрутизируем по `payload` (`{"cmd": "faq"}`), а не по
  тексту кнопки: текст кнопок будут менять.
- Кнопки типа `callback` порождают событие `message_event`; на него обязательно ответить
  `messages.sendMessageEventAnswer`, иначе у пользователя крутится индикатор загрузки.
- У старых клиентов клавиатуры может не быть — каждая команда должна работать и текстом.

## Сценарий поддержки

Состояние диалога храним в Postgres (не в памяти — на Railway процесс перезапускается).

**Пользователь**

| Команда / кнопка | payload | Что делает |
|---|---|---|
| «Начать», «Меню» | `{"cmd":"menu"}` | Приветствие и главное меню |
| «Частые вопросы» | `{"cmd":"faq"}` | Список тем inline-кнопками, ответ из таблицы `faq` |
| «Написать оператору» | `{"cmd":"ticket_new"}` | Просит описать проблему, следующее сообщение создаёт обращение |
| «Мои обращения» | `{"cmd":"ticket_list"}` | Открытые обращения и их статус |
| «Закрыть обращение» | `{"cmd":"ticket_close","id":N}` | Закрывает, просит оценку 1–5 |

Пока у пользователя есть открытое обращение, любое его сообщение (включая вложения) добавляется
в это обращение и уходит в дашборд. В нерабочее время (`WORK_HOURS`) обращение создаётся как
обычно, а пользователь получает автоответ со временем, когда ждать ответа.

**Оператор** работает в дашборде. Единственная ВК-команда — `/link` от `ADMIN_ID`: бот отвечает
одноразовой ссылкой на регистрацию passkey, живёт 10 минут, сгорает после использования.
Сообщения от всех остальных отправителей, не относящиеся к обращениям, игнорируем молча.

## Схема БД

- `users(vk_id PK, first_name, last_name, photo_url, can_write, state, state_data jsonb, created_at, last_seen_at)`
- `tickets(id PK, user_id, status open|in_progress|closed, rating NULL, created_at, first_reply_at, closed_at, last_message_at, unread_count)`
- `ticket_messages(id PK, ticket_id, direction in|out, text, attachments jsonb, vk_message_id, created_at, read_at)`
- `faq(id PK, title, answer, position, is_active)`
- `processed_events(event_id PK, created_at)` — защита от повторов Callback API, чистим старше суток
- `outbox(id PK, peer_id, payload jsonb, random_id, attempts, next_attempt_at, status, last_error)`
- `admin_credentials(id PK, credential_id bytea UNIQUE, public_key bytea, sign_count, transports, name, created_at, last_used_at)`
- `sessions(id PK, created_at, expires_at, user_agent)`
- `push_subscriptions(id PK, endpoint UNIQUE, p256dh, auth, created_at, last_ok_at)`
- `setup_tokens(token_hash PK, expires_at, used_at)`

## Дашборд

- Экраны: Диалоги (очередь + чат), FAQ, Статистика, Настройки.
- Реалтайм — WebSocket `/ws`, авторизация той же сессионной кукой. Дашборд закрыт → веб-пуш.
- Оператор никогда не вводит ID. Все действия — клик по элементу списка или кнопка внутри чата.
- Стиль: тёплый светло-серый фон, белые карточки радиусом ~28px, мягкие тени, крупные градиентные
  акценты (lime/coral/green) на статистике, пружинные анимации, плотный трекинг на числах.
  Светлая тема основная, тёмная поддерживается.

**Пуши на iOS.** Работают только с iOS 16.4+, только если PWA добавлена на экран «Домой», и
разрешение запрошено по нажатию кнопки. iOS периодически сбрасывает подписку — переподписываемся
при каждом запуске. Если открыто не как PWA, показываем подсказку «Поделиться → На экран Домой».

## Правила работы

- Каждый обработчик покрываем тестом на уровне «событие → вызовы VK API» с замоканным отправителем;
  реальные запросы к ВК в тестах не делаем.
- Ошибки VK API логируем с кодом и методом, но без токена и без текста сообщений пользователей.
- Массовых рассылок в этом боте нет: бот отвечает только в рамках обращений. Если понадобится
  рассылка — отдельная задача с проверкой `messages.isMessagesFromGroupAllowed` и лимитами.
- Перед тем как считать задачу готовой: тесты зелёные, `ruff` без ошибок, бот стартует
  с `VK_MODE=longpoll` локально.
